# نشر نسخة مستقلة على Vercel

هذه التعليمات للنسخة الموجودة في حسابك على Vercel، ولا تغيّر اتصال موقع Lovable الحالي.
تم إعداد المشروع لاختيار Vercel تلقائياً عند وجود `VERCEL=1`، مع الحفاظ على إعدادات نشر Lovable.

## 1. جهّز قاعدة بيانات تملكها

أنشئ مشروعاً جديداً لدى مزوّد قاعدة البيانات الذي اخترته للنسخة المستقلة. يجب أن يكون متوافقاً مع عميل Supabase الموجود في المشروع (PostgreSQL مع Data API ومفتاح خادم).
للمشروع الخارجي الحالي الذي يحتوي بيانات، نفّذ `deployment/external-database.sql` مرة واحدة في محرر SQL في حسابك الخارجي. ينشئ جداول منفصلة باسم `bakri_members` و`bakri_candidates` و`bakri_votes` و`bakri_settings` دون تغيير الجداول الموجودة. لا تستخدم `deployment/database.sql` لهذا المشروع؛ ذلك الملف مخصص لمشروع فارغ.
الجداول مقفلة أمام المتصفح؛ جميع الطلبات تمر عبر دوال الخادم، وتعديلات الإدارة تحتاج إلى جلسة إدارة صحيحة.

يحتاج الموقع فقط إلى رابط مشروعك الخارجي ومفتاح الخادم الخاص (`service_role` أو `sb_secret_`)؛ المتصفح لا يتصل مباشرة بقاعدة البيانات. المفاتيح المحفوظة في Lovable لا تنتقل تلقائيًا إلى Vercel؛ أضف قيم مشروعك الخارجي في Vercel أيضًا.

## 2. أضف المتغيرات في Vercel

افتح مشروعك في Vercel ثم **Settings → Environment Variables**. أضف القيم التالية لمحيط Production، وكذلك Preview إذا أردت اختبار النسخ التجريبية:

| الاسم | القيمة |
| --- | --- |
| `EXTERNAL_SUPABASE_URL` | رابط مشروع قاعدة البيانات الخارجي |
| `EXTERNAL_SUPABASE_SERVICE_ROLE_KEY` | مفتاح الخادم الخاص من المشروع الخارجي، وليس المفتاح العام |
| `ADMIN_PASSWORD` | كلمة مرور جديدة خاصة بالإدارة |
| `SESSION_SECRET` | نص عشوائي طويل لا يقل عن 32 حرفاً |

أنشئ سر جلسة قويًا باستخدام مولد آمن واحفظه مباشرة في Vercel. **لا تضف `VITE_` إلى مفتاح الخادم أو كلمات المرور.** لا تضع الأسرار في GitHub، ولا تستبدل ملف `.env` الخاص بنسخة Lovable. يختار الموقع الجداول الخارجية المنفصلة على Vercel فقط؛ يبقى موقع Lovable متصلًا ببياناته الحالية.

## 3. إعداد المشروع والنشر

استورد نفس مستودع GitHub في Vercel أو حدّث الاستيراد الموجود، واختر:

- Framework Preset: **Other** (المشروع يجهز دوال الخادم بواسطة Nitro).
- Install Command: `bun install --frozen-lockfile`.
- Build Command: `bun run build`.
- Output Directory: لا تحدد `dist`؛ اترك التخصيص فارغاً. الإعداد يولّد صيغة Vercel الكاملة في `.vercel/output`، وليس صفحات ثابتة فقط.
- إذا لم يضف Vercel المتغير `VERCEL` تلقائياً، أضف `VERCEL=1`.

احفظ ثم اضغط **Redeploy**. لا يكفي تغيير المتغيرات دون إعادة النشر.

## 4. تأكد من التشغيل

1. افتح `/` ثم `/vote` وتأكد أن الصفحتين تفتحان بعد تحديث المتصفح.
2. افتح `/admin` وسجّل الدخول بكلمة المرور الجديدة.
3. أضف الأب من الإدارة باسم رباعي؛ ثم أضف الابن باسم رباعي مع اسم الأب الثلاثي أو الرباعي المطابق.
4. الطلبات من الصفحة العامة تبقى معلقة حتى قبولها. بعد القبول سيظهر الابن تحت أبيه.
5. أضف ثلاثة أشخاص لقسم الكبار وستتحرك أسماؤهم بشكل متصل.
6. جرّب التصويت مرة ثم إعادة المحاولة من المتصفح نفسه.

الجداول المنفصلة تبدأ فارغة. البيانات الموجودة على Lovable لا تنتقل تلقائيًا. لا تحذفها من الموقع الحالي ولا تشغّل نسخة Vercel قبل إكمال نقل الأفراد والصور والمرشحين والأصوات والإعدادات والتحقق منها. لإخراج نسخة بياناتك الحالية استخدم **More → Database → Manage → Settings → Export data**، ثم أرفق التصدير لإكمال النقل إلى الجداول المنفصلة.

## حدود التحقق

تم التحقق من صلاحية الاتصال بالمشروع الخارجي، لكن الجداول الحالية فيه تختلف عن حقول هذا التطبيق؛ إنشاء الجداول المنفصلة ونقل البيانات والنشر الفعلي ما زالت غير مكتملة.
إذا فشل فتح الصفحة، راجع سجل الدوال في Vercel للمتغير المفقود أو رسالة الخطأ؛ نجاح البناء وحده لا يثبت اتصال قاعدة البيانات.
